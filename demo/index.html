The system under test

Four agents, run on the client's own cloud.

Intake Agent
Reads the request, extracts procedure, diagnosis, history.
Policy Retriever
Finds the payer's current coverage policy.
Criteria Checker tool
Checks the case against the policy's medical criteria.
Decision Writer
Drafts approve / deny / send to a nurse reviewer, with citations.

Where the failures came from

28 failed cases, attributed by trace to the agent that caused them.

Main finding: the Policy Retriever often returns superseded policy versions, so the system approves care under rules that no longer apply. See an example trace →

Root cause: the retriever ranked policy LBP-2025-11 (superseded in July 2026) above the current LBP-2026-07. The criteria checker and writer then did their jobs correctly, on the wrong rules. Fix: filter by effective date before ranking. Tested in candidate 2.4 → see the release gate.

What the gate found

The fix worked. The model upgrade introduced new problems.

  • Accuracy and policy citations now pass. The retriever fix works.
  • The new writer model quoted the member's full diagnosis history in 2 denial letters. That's more patient data than needed.
  • It sent fewer unclear cases to a nurse reviewer (91.0%, target 95%).

Recommendation

From the EvalTrust validator.

Ship the retriever fix with the current writer model (tested as 2.4b: all 6 checks pass). Re-submit the model upgrade after adding a minimum-necessary filter to the letters.

EVALTRUST · INDEPENDENT VALIDATION REPORT

PriorAuth Assistant: production readiness

Client: Northwind Health (sample) · Report EVT-2026-014 · 6 Nov 2026 · Versions tested: 2.3, 2.4, 2.4b

1. Scope

A four-agent system that drafts prior-authorization decisions for nurse review. Out of scope: the claims system, member-facing chat.

2. Method

Acceptance criteria were agreed and signed before testing. 240 de-identified real cases (golden dataset v1.2). Blind grading by two clinical reviewers plus a judge model. All testing ran inside the client's cloud account, with zero data retained by EvalTrust.

3. Results

CriterionTargetv2.3v2.4b

4. Findings

F1. Superseded policies retrieved in 21 of 28 failures (v2.3). Fixed in 2.4b.
F2. Upgraded writer model over-shares patient history (v2.4). Not released.

5. Recommendation

Release 2.4b to production with the release gate active on every change, and monthly monitoring of 5% of live traffic.
